# 应用场景

## 典型使用场景

### 1. 算法工程师日常研发

- **需求**：频繁创建训练任务、挂载数据集与模型、查看任务状态与日志。
- **使用方式**：在「训练」中创建/停止任务，在「数据集」「模型」中管理版本；通过「应用」中的训练模板一键生成任务配置，减少重复填参。
- **价值**：减少在网页控制台与本地脚本间切换，参数模板化后出错更少。

### 2. 推理服务上线与运维

- **需求**：部署/扩缩容/下线在线推理服务，查看实例状态与资源占用。
- **使用方式**：在「部署」中按队列或关键词查服务，基于模板或自定义配置创建服务，必要时删除或重建。
- **价值**：统一入口管理多套服务，配合「计算资源」查看队列与资源池负载。

### 3. 批量任务与数据处理

- **需求**：提交与管理以「task-」为代表的批量任务，跟踪执行情况。
- **使用方式**：在「任务」中查看任务列表与详情；通过「应用」中的任务类模板快速创建任务。
- **价值**：批量任务集中可见，便于排查与统计。

### 4. 数据集与模型生命周期

- **需求**：上传/注册数据集与模型，做版本管理，并与训练、部署流程衔接。
- **使用方式**：在「数据集」「模型」中完成创建、版本、删除；在训练/部署时选择对应版本。
- **价值**：数据与模型在控制台内可追溯，与训练、部署形成闭环。

### 5. 资源与成本观测

- **需求**：了解各队列、资源池的 GPU/CPU/内存使用，做容量与成本评估。
- **使用方式**：在「计算资源」中查看队列、资源池、加速卡与 CPU/内存信息。
- **价值**：为扩容、缩容与预算提供依据。

### 6. 团队标准化与协作

- **需求**：统一部署与训练流程，新人快速上手。
- **使用方式**：将常用配置沉淀为「应用模板」，在「应用」中一键部署或创建训练/任务；在「系统设置」中统一维护 AK/SK 与资源池/队列等配置。
- **价值**：减少因人而异的配置差异，降低误操作风险。

## 最佳实践建议

- **首次使用**：先在「系统设置」中配置并保存 AK/SK 及资源池/队列等，再在「概览」与「计算资源」确认可见性。
- **日常动线**：数据准备（数据集）→ 训练（训练 + 可选应用模板）→ 模型管理（模型）→ 上线（部署 + 可选应用模板）。
- **批量任务**：优先使用「应用」中的任务模板，保证命名与参数规范，便于在「任务」中筛选与排查。
- **安全**：AK/SK 仅保存在本机或内网环境的配置中，不要提交到代码仓库；生产环境建议使用独立子账号或最小权限 AK/SK。
