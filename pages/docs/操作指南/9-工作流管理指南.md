# 9. 工作流 (Workflow) 管理指南

对于大型且复杂的人工智能应用，单纯跑一发任务或者单纯发个在线服务早已无法满足需求。真实的工业场景通常包含一串承上启下的流水线（Pipeline）。

在 **「工作流」** 模块中，您可以将平台散落的这许多孤立算力模块有机编排到一起。

## 工作流编排的核心概念

一份完整的工作流通常包含了 **DAG (有向无环图)** 概念定义的多个流转节点，例如：
1. **数据拉取与清洗**（调用一个 Task 运行数据处理容器） -> 
2. **将产物挂载进训练环节**（自动触发一次 Training 分布式微调任务） -> 
3. **输出评测与转换**（将 checkpoint 压缩/转为可执行包） -> 
4. **灰度发布**（挂载产出权重自动发配一个新版本的在线部署 Deployment 服务）。

## 使用 Web 编排器 (Workflow Editor)

在 **「工作流」** 面版点击 **「编辑/新建工作流」**：
平台自带了一套可视化的 Web 编辑器（Workflow Editor）：

### 节点与连接配置
* **节点拉取**：您可以从左侧控件面板直接拖拽各种动作模版（譬如“执行某个脚本”、“创建一项训练”、“延迟计时”）至中间画布。
* **绘制依赖关系**：将代表“上游产物”节点的连线指向“下游接收节点”。只有当上个节点在云端运行完毕且状态为 `Success` 绿灯时，后面的机器资源才会被触发启动。

### 参数透传
* 在长跨度的图链路中，最前置步骤（如定义今天跑数据的日期字符串和分支）可以通过**全局变量 (Variables) / 输入参数 (Inputs)** 的形式被带入并向下文传递给所有节点里的 JSON 设置，实现一次触发，全栈自动执行的作用。

## 工作流触发与状态监控
1. **手动/定时触发**：对于编写好的 Workflow 模板，通过启动面板可对其传入启动必填变量，触发其实例化运行。
2. **实例看板排错**：由于步骤众多，系统会实时反显这个 Workflow 实例当前已经跑到了 DAG 图上的什么阶段。您可以点击正在转动的环形图标节点，探囊取物地直接查看这个步骤所触发的具体容器或者内部函数的实况报错 Log（这也是极佳的长痛排错大盘）。
3. **重跑与断点续转**：如果因为某一环节环境配错而抛锚，你只需要修复该局部节点错误并点击「从中断处重试」即可继续链路，无需为前面耗费数小时成功的计算做无谓重工消耗。
