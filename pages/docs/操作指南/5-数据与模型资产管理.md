# 5. 数据与模型资产管理

算法团队的产出与血液永远是数据及算法成果。在 MLP Cooker 中，数据集、模型、镜像、任务统一归入左侧导航 **「AI资产」**；文件级浏览（存储桶 / PFS）请前往 **「资源 → 存储」**。

## 数据集管理与 lakeFS 集成

进入 **「AI资产 → 数据集」**。
### 1. 存储类型查询
系统内置了对两类核心存储协议的查询适配：
*   **BOS (Baidu Object Storage)**：适用于低成本存放大量的闲置图文视频数据或大规模离线仓库池。
*   **PFS (Parallel File System)**：更昂贵的高性能并行文件系统，常常被挂载用来供训练时以最高 IO 速度吞吐读取数据集。
您可以通过顶部切换选项框进行快速筛选。

### 2. lakeFS Git-like 版本化管控 (BOS 独占)
针对 BOS 存储上的大型数据集修改，MLP Cooker 深层集成了 **数据版本化管理架构**：
1. **创建仓库：** 在数据集管理列表，选中一个基础的 BOS 数据集并在操作栏点击“创建仓库”。
2. **生成绑定：** 系统会帮您预填写各种配置并将该路径提升为具有隔离版本层的数据池。
3. **版本分支管理：** 数据集不再是混乱的增删改，团队可以像管理代码一样使用 Branch、Commit、Merge 等逻辑管控清洗后的各版本语料库。

## 模型 (Model) 版本管理

在训练与微调完成之后，模型权重与配方的导出地即成为了**模型资产库**。进入 **「AI资产 → 模型」** 页面即可阅览。
*   **按模型溯源**：查看到底有几款正在被维护的算法模型体系。
*   **多版本追踪**：针对某个架构（比如 `Llama-3-8B-Base` 系列），点进去能够查阅它的 V1、V2、V3 等多个迭代版本号节点，追踪它们分别部署在了哪里、存储在 BOS 的哪个固定安全桶等元数据信息。
*   **版本回退与对比**：确保如果有某个微调部署后在生产环境翻车，您可以快速回到本页面根据上个稳定性良好的模型版本 ID 重置，再通过「应用」引用对应模板发起部署。
