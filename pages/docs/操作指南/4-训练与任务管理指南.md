# 4. 训练与任务管理指南

在大中型模型微调及海量数据批处理场景下，使用 MLP Cooker 的 **训练 (Training)** 和 **任务 (Task)** 管理模块能有效调度平台算力资源，并进行多卡及多机网络并行训练。

## 训练作业 (Training Jobs) 管理

进入导航栏的 **「训练」** 页面：
该页面专注于管理带有拓扑并行与通信架构（如 MPI 等角色分组机制）的长周期训练任务。

### 1. 发起训练任务
训练任务可以通过手工或经从「应用」一键触发。主要配置考量点：
*   **节点配置**：如果是分布式训练，可在此处定义多个节点规格以及网络要求。
*   **数据集挂载**：能够将 BOS 的某个 lakeFS 缓存快照或 PFS 直接挂载入训练容器之中作为输入路径。
*   **输出路径**：设置模型权重/Checkpoint 会被导出到的云端路径，避免因计算中断而丢失珍贵产出。

### 2. 状态查询与干预
*   **进度监视**：平台会定期同步 AIHC 底层的状态流转。
*   **实时停止**：若监控到 Loss 发散或参数填错，可在操作栏快速点击“停止”，释放卡槽，为后面的队列排期让路。
*   **销毁工作区**：由于训练通常占据宝贵的 PFS/缓存和系统开销，完成的离线任务可以通过“删除”清理追踪。但最终模型资产或数据集均会被安全持久化下来。

## 批量任务 (Task) 调度

有时候，我们需要执行跑一些自动化数据打标，清洗，或者转换这类简单的“一把过”脚本，这时候推荐使用 **「任务」** 管理页面。

*   **专一性过滤**：平台自动过滤包含特定前缀规律（如 `task-` 开头）的单节点离线作业，与模型训练独立开来。
*   **创建与详情**：这套体系省去了复杂的主从节点拓扑配置，仅需指定镜像地址、执行的入口脚本 (`command/entryPoint`) 以及算力数量与环境变量，极大地降低了数据清洗组用户上手云上资源调度的门槛。
*   **状态查探**：一旦提交执行，随时点进该任务的详情页面查探它的 Stdout 将非常方便于监控这批离线清洗日志。
